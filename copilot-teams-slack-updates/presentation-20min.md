### デモ① セットアップ〜README 更新（4:00-6:00 / 2分）

**やること**: `@GitHub README を最新の構成に更新して` と投げる

**見せるポイント**:

- メンションするだけでタスク分解が始まる（0/4 の進捗バー）
- 数分で PR が出来上がる
- PR の説明文に「Created from a Microsoft Teams conversation」と自動で入る

**スクショ参照**: img-06（タスク分解）→ img-07（完了）→ img-08（PR）

**話すこと**: 「会議中に出たアクションアイテムを、その場でエージェントに投げると、会議が終わる頃には PR ができてる、という世界観です」

---

### デモ② エラー修正＋リポジトリ不一致ハプニング（6:00-10:00 / 4分）⭐ 山場

**やること**: トレースバックを貼って「このエラー直して」

**見せるポイント（ここが一番の見せ場）**:

1. まず普通に依頼 → Copilot が「このスレッドは Foundry- リポジトリのままですが、Test-Repo に切り替えますか？」と**自分で設定ミスを検出**
2. 「切り替えて」と返す → 即座に切り替えて修正完走 → PR #1 作成
3. 修正内容の報告が「原因・修正内容・動作確認」までフルセット

**スクショ参照**: img-09（依頼）→ img-10（不一致検出）→ img-11（修正完了）→ img-12（PR）

**話すこと**: 「9/25 アプデの信頼性改善が効いてる場面です。前の設定が残ってても、勝手に間違ったリポジトリを探しに行かず、状況を説明して確認を取ってくる。これ、結構感動しました」

**失敗談も挟む**: 「ちなみに最初に画像添付で送ったら『I couldn't read these images』って読み取り失敗しました。でも Copilot の言う通りもう一度添付し直したら読めたので、エラーが出たらリトライがコツです」（img-19 を見せる）

### 📄 Slide 7: チーム導入のヒント（15:30-17:00）

**見出し**: 「明日から試すために」

導入手順（5ステップ）:

1. 管理者が cloud agent ポリシー + クラウドサンドボックスを有効化
2. GitHub app for Teams をインストール
3. `@GitHub` でアカウント連携
4. デフォルトリポジトリを設定
5. `@GitHub` に続けてタスクを書いて送信

コスト面:

- 既存の AI クレジットの枠組みで消費
- クラウドサンドボックスは別途課金
- 予算管理は既存の usage-based billing budgets で制御可能
