## はじめに

この記事は、最近のAIエディタやコーディングアシスタント（GitHub Copilot、Claude Codeなど）で配布・利用される「Plugin（プラグイン / Extensions / Tools）」について、どのような仕組みで動いているのか、そしてどうやって実践的に使っていけるのかを自分なりに整理した学習メモです。

AIエディタがコードを書いてくれるだけでなく、「ローカルの環境」や「外部のツール」と連携し始めている今、「エディタ拡張としてのプラグイン」の具体的な仕組みと使い方を考えてみたいと思います。

**対象読者:**

- GitHub Copilot Extensions や Claude Code のプラグイン機能に興味がある方
- MCP（Model Context Protocol）という単語を聞くようになったが、メリットが知りたい方
- 私と同じように、新しい技術要素を学習・整理したい初学者の方

---

## 1. AIコーディングアシスタントにおける Plugin とは？

GitHub CopilotやClaude CodeにおけるPlugin（またはExtensions、ツールの連携）とは、**「AIエディタに対して、プロジェクト固有の文脈（Context）や、手足となるアクション（Action）を後付けで追加する仕組み」**です。

LLMはコードの生成は得意ですが、「現在PC上で動いているデータベースの中身」や「Jiraに登録された最新のIssueチケットの内容」は直接見ることができません。
そこで、AIエディタに「特定のコマンドを実行させる」「外部APIから情報を取得させる」ためのインターフェースを提供するのが、ここでのPluginの役割です。

---

## 2. 話題の「MCP（Model Context Protocol）」との関係

最近、このAIプラグイン領域で一気にデファクトスタンダードになりつつあるのが、Anthropicなどが提唱している **MCP（Model Context Protocol）** です。

これまで、各エディタやAIツールは独自の形式でプラグインを作らなければなりませんでした。しかし、MCPという「共通の通信規格」に対応することで、**「1度MCPサーバー（プラグインの実体）を作れば、Claude Codeでも、GitHub Copilot（連携経由などで）でも、様々なAIツールで同じ能力を使い回せる」**ようになります。

### AIとエディタの連携フロー（仕組み）

1. **ユーザーの指示**：「Copilot/Claude、このJiraチケット(PRJ-123)の内容を読んで、必要なAPIを実装して」
2. **AIの判断**：「Jiraチケットの中身を知るために、『Jiraプラグイン（MCPサーバー）』の `get_issue` ツールを使おう」
3. **ローカルサーバー連携**：エディタがローカルで動いているプラグインにリクエストを投げる
4. **データの受け取り**：プラグインがJiraからデータを取得してAIに返す
5. **コード生成**：AIがその要件をもとにコードを生成し、エディタ上に提案する

## 3. なぜ今、このPluginを学ぶのか？

自分がなぜこれを学ぶべきだと思った理由は以下の通りです。

1. **「コピペ」から「自動処理」への進化**
   これまではブラウザで情報を調べてAIに貼り付けていましたが、プラグインがあればAIが自律的に情報を集めて（Research）、コードを書き（Code）、テストを実行して（Test）くれるようになります。
2. **自社・自分専用のAIアシスタントが作れる**
   社内の独自APIや、自分なりの開発ワークフローに特化したツールの設計図を書けるようになれば、生産性が爆発的に向上すると感じています。

## 4. 使い方を考える（自分ならどんなPluginを作るか？）

学習の次のステップとして、「自分だったらエディタ向けにどんなPlugin（MCPサーバー等）を作るか？」を考えてみました。

### アイデア1：CI/CD ログ解析＆自動修正プラグイン

- **機能**: GitHub Actionsなどでビルドが落ちた際、エラーログのIDを渡すと、プラグインがエラーログの全文を取得してAIに渡し、AIが修正コードを直接エディタに提案してくれる。
- **メリット**: ブラウザとターミナルとエディタを行き来するコンテキストスイッチがゼロになる。

### アイデア2：プロジェクト固有のDBスキーマ参照プラグイン

- **機能**: ローカルで立ち上がっているDocker上のPostgreSQLに接続し、「現在のusersテーブルの構造を教えて」といったAIからのクエリ（SQL）を実行・結果を返すツール。
- **メリット**: AIが「架空のテーブル構造」を幻覚（ハルシネーション）で書くミスを防ぎ、実環境に即した正確なSQLやORMのコードを生成できる。

## まとめ

今回の学習で、以下のことが理解できました。

1. GitHub CopilotやClaude Code向けのPluginは、AIに「エディタ外のローカル環境や外部サービスとやり取りする手足」を与えるものである。
2. その基盤技術として「MCP（Model Context Protocol）」が台頭しており、作れば様々なツールで使い回せる時代が来ている。
3. 自作することで、コンテキストスイッチを減らし、完全に自分たちのプロジェクトにローカライズされた強力な相棒になる。

**次のステップ:**
今回は概念の理解とアイデア出しでした。
次は実際に簡単なMCPサーバー（PythonやTypeScriptなど）をローカルで立ち上げ、Claude Codeやエディタ上から自分のローカルファイルやダミーAPIを操作させるチュートリアルをやってみたいと思います。
